# 下一代生成式推荐系统综述

## 一、引言

传统推荐系统的核心问题是：

> 在一个给定内容池中，针对一个用户，选出最可能带来点击、停留、转化或满意度提升的内容。

因此，经典推荐系统通常围绕以下要素展开：

- 用户画像
- 内容表示
- 行为序列
- 召回
- 排序
- 多目标优化

但随着大模型、agent、生成式内容和多步交互系统的发展，推荐系统所面对的问题正在发生根本变化。

系统不再只是“从池子里挑内容给用户”，而越来越多地需要回答：

- 当前上下文下，下一步最值得发生什么？
- 系统应当向用户推荐什么行动、什么方向、什么工作上下文？
- 如何让推荐本身参与后续生成、执行与状态演化？
- 如何在开放世界里，从“已有内容分发”转向“下一步上下文构造”？

这意味着，推荐系统正在从一个内容分发系统，演进为一个上下文演化系统。

如果说传统推荐的核心是 `user -> item`，那么下一代生成式推荐系统的核心正在变成：

```text
state -> next move -> next context
```

## 二、什么是“生成式推荐”

“生成式推荐”不是简单地用大模型生成几句推荐文案，也不是在原有排序系统上套一层 LLM 包装。

更准确地说，生成式推荐意味着：

> 系统不仅从既有候选集中选择内容，还能够构造、改写、组合、适配甚至生成“下一步值得进入的机会”。

这里的“生成”至少包含三层含义：

### 1. 候选生成

推荐对象不再局限于已有 item，还可能是：

- 一个行动建议
- 一个任务步骤
- 一个工作流节点
- 一个继续创作的方向
- 一个交互模式
- 一个上下文注入结果

### 2. 上下文生成

系统不仅决定“给什么”，还决定：

- 下一步该围绕什么工作
- 该带入哪些对象、约束、玩法模式
- 应该如何组织 agent 的 working context

### 3. 表达生成

系统可以将内部选中的候选，重写成更自然、更有拉力、更贴当前语境的 surface form。

因此，生成式推荐的“生成”本质上不是文字生成，而是：

> 候选空间、工作上下文和推荐表达的联合生成。

## 三、下一代推荐系统的核心转向

### 1. 从推荐内容到推荐下一步

传统推荐推荐的是内容对象。
下一代推荐推荐的是：

- 下一步动作
- 下一步工作上下文
- 下一步可执行机会

推荐对象从 `item` 演进为 `next move`。

### 2. 从用户中心到状态中心

传统推荐系统的主轴是用户偏好。
下一代生成式推荐系统的主轴更可能是：

- 当前状态
- 当前任务
- 当前会话
- 当前环境
- 当前世界

用户画像仍然重要，但它不再总是第一驱动力。更常见的是：

1. `task/world fit`
2. `session fit`
3. `user preference fit`

也就是说，个性化从主干退为调制层。

### 3. 从分发到演化

传统推荐的结果更多是“被消费”。
生成式推荐的结果则会：

- 触发行动
- 生成新内容
- 更新状态
- 改变下一轮推荐空间

因此它天然形成闭环：

```text
current state
-> recommendation
-> action / generation
-> state update
-> next recommendation
```

推荐不再只是分发，而是在推动系统演化。

## 四、核心抽象：从 item 到 work-context

如果继续抽象，下一代生成式推荐系统真正的核心对象，不是 item，也不是 suggestion，而是：

> `work-context`

所谓 `work-context`，指的是一组最小但足以支撑下一步执行的上下文包。它通常包含：

- 当前 focus 是什么
- 当前 goal 是什么
- 当前要继承什么 tension / constraints
- 当前适合使用什么模式
- 当前推荐的 action 是什么

换句话说，系统真正推荐的不是“一个内容”，而是：

> 一个最值得进入的工作上下文。

这也是为什么下一代推荐系统和 agent 天然耦合。因为 agent 真正需要的不是 item，而是：

- 下一步该处理什么
- 用什么上下文处理
- 如何把当前状态推进到更有价值的下一状态

## 五、推荐系统的新最小闭环

从工程抽象看，一个更适合生成式推荐系统的最小对象集合是：

```text
Context -> Intent -> Opportunity -> Action -> Outcome
```

### Context

当前决策所需的现实切片。

### Intent

系统对当前目标的判断。

### Opportunity

当前成立的下一步机会。

### Action

如果选择这个机会，系统要做什么。

### Outcome

动作之后发生了什么，以及结果如何写回状态。

这套抽象比传统 `user/item/feature` 更适合描述 agent-native、生成式、多步交互系统。

## 六、系统架构：为什么不能纯规则，也不能 LLM 端到端

### 纯规则的局限

纯规则系统的问题是：

- 难以理解长文本、复杂作品和多轮会话
- 难以抽出 latent tension、玩法模式和未完成目标
- 难以在开放场景中保持表达丰富性

### 端到端 LLM 的局限

纯 LLM 端到端系统的问题是：

- 不可控
- 不可解释
- 成本高
- 易漂移
- 难做多目标约束
- 难做状态写回与长期演化

因此，下一代推荐系统最合理的形态不是二选一，而是：

> 结构化 runtime + LLM 增强

也就是：

- state / retrieval / policy 骨架由系统控制
- LLM 插在语义理解和表达生成等关键位置
- 最终决策层保持可控、可解释、可调优

这可以称为：

> stateful, policy-controlled, LLM-augmented recommendation runtime

## 七、LLM 在下一代推荐中的合理位置

### 最适合的位置 1：语义钩子提取

从文本、作品、对话、工具结果中提取：

- tension
- relationship
- lore gap
- visual opportunity
- goal shift
- unresolved loop

这是规则难做好的部分，LLM 很适合。

### 最适合的位置 2：外部模式抽象

从其他世界、任务或内容中抽象出：

- play pattern
- narrative move
- interaction structure
- pacing template

然后供系统做迁移注入。

### 最适合的位置 3：offer 文案重写

候选已经选定后，LLM 可以负责：

- rewrite headline
- rewrite prompt
- rewrite whyNow

即让推荐更自然、更有拉力。

### 不适合交给 LLM 的部分

不适合由 LLM 直接统管的部分包括：

- 最终排序
- 预算控制
- 状态写回
- durable memory promotion
- 多目标策略仲裁

这些更适合显式 policy。

## 八、状态成为新的核心基础设施

在生成式推荐系统中，`state` 不再只是用户画像，而是：

> 支持下一步检索、决策、执行和写回的当前现实表示。

它通常至少分为：

- durable state
- session state
- working state
- outcome state

随之而来的核心基础设施包括：

- context write protocol
- session compression
- working context assembly
- memory promotion
- feedback projection

因此，下一代推荐系统的关键难题之一已经不再是“如何排序内容”，而是：

> 如何管理不断增长、不断变化、不断被执行结果改写的上下文。

## 九、两层推荐：内生推荐与外部注入

在更成熟的生成式推荐系统里，推荐往往需要分成两层。

### 第一层：内生推荐

即从当前状态内部自然长出的下一步。

它强调：

- 自洽
- 连续性
- 当前世界或任务自己的演化逻辑

### 第二层：外部模式注入

即从其他系统、其他内容、其他世界中抽取可迁移模式，对当前状态进行增强。

它强调：

- 新鲜感
- 玩法结构
- 节奏增强
- 可迁移的外部先例

这两层共同作用：

- 第一层保证真实
- 第二层保证花样

最终，两者都收敛成同一种推荐对象：`work-context`。

## 十、与 agent 的关系

生成式推荐系统和 agent 的关系，不应被理解为“agent 顺便调用推荐”。

更准确地说：

> 下一代推荐系统是给 agent 推荐当前 state 下最值得进入的 working context 的引擎。

流程更像：

```text
current context
-> recommendation / transition engine
-> choose next move
-> build working context
-> inject into agent
-> agent executes
-> state update
```

也就是说：

- 推荐系统决定“下一步应该做什么”
- agent 负责“在被选中的上下文里执行”
- 执行结果再反过来更新推荐空间

因此，推荐系统逐渐成为 agent 系统中的 decision layer。

## 十一、评估方式也会改变

传统推荐系统看：

- CTR
- dwell time
- GMV
- conversion

生成式推荐系统需要增加新的指标：

- next-step acceptance
- execution continuation rate
- same-context depth
- state progression quality
- pattern reuse quality
- world/task momentum
- user-perceived fun / pull

因为生成式推荐真正优化的是：

> 用户是否愿意继续进入下一轮上下文，而不是只点一下。

## 十二、未来形态：推荐系统作为上下文演化引擎

综上，下一代推荐系统不应被理解为“更聪明的召回排序系统”，而应被理解为：

> 一个通过理解当前状态、构造下一步机会、选择最佳过渡动作，并推动系统进入更高价值下一上下文的引擎。

从这个意义上说，它的本质是：

- context-driven
- stateful
- agent-facing
- action-linked
- evolution-oriented

也就是说，它正在从“内容推荐系统”变成：

> context transition engine

## 十三、结语

下一代生成式推荐系统的核心，不是把 LLM 接进推荐链路，也不是把传统召回排序换个名字，而是：

- 推荐对象从 `item` 变成 `work-context`
- 驱动逻辑从 `user preference` 变成 `state transition`
- 系统目标从 `content consumption` 变成 `context evolution`
- LLM 的作用从“端到端生成”变成“语义理解与表达增强”
- 推荐系统的角色从“分发器”变成“agent 的决策与上下文供给层”

如果要用一句话概括：

> 下一代生成式推荐系统，是一个由当前 context 驱动、为用户与 agent 共同构造下一步最佳 work-context 的上下文演化引擎。
