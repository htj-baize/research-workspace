# 下一代推荐系统总结报告

## 一、核心判断

下一代推荐系统不再主要回答：

- 这个用户下一条最可能点击什么内容

而是逐渐转向回答：

- 在当前状态下，什么是最值得进入的下一步上下文
- 系统应该把用户、世界和 agent 推向哪一个更有价值的下一状态

这意味着推荐问题正在从：

```text
user -> item
```

演进成：

```text
state -> next move -> next context
```

推荐系统的输出也不再只是 item，而更像是：

- next-step offer
- action recommendation
- play pattern
- working context
- agent execution context

换句话说，下一代推荐系统正在从“内容分发引擎”变成“context transition engine”。

## 二、与传统搜广推的根本区别

传统搜广推的主轴通常是：

- 用户长期偏好
- 内容池
- 召回与排序
- CTR / 时长 / 转化

而在生成式创作、世界构建、agent 协作这类场景里，推荐的主轴变成了：

- 当前世界状态
- 当前任务与当前会话
- 当前未完成张力
- 当前最值得推进的下一步

因此，个性化虽然仍然重要，但它不再是第一驱动力。更合理的层次是：

1. `world/task fit`
2. `session fit`
3. `user preference fit`

也就是说，用户画像更像是一种偏置项、调制项和风格层，而不是主排序轴。

## 三、下一代推荐系统的核心对象

我们讨论后得到的最小公共抽象是：

```text
Context -> Intent -> Opportunity -> Action -> Outcome
```

其中：

- `Context`：当前决策所需的现实切片
- `Intent`：系统判断的当前目标
- `Opportunity`：当前成立的下一步机会
- `Action`：如果选择该机会，系统具体做什么
- `Outcome`：动作之后发生了什么，以及如何写回状态

这一抽象比传统 `user/item/feature` 更贴近 agent-native 系统，也更能承载生成式创作与多步协作。

## 四、从推荐 item 到推荐 work-context

下一代推荐系统的一个关键变化，是推荐对象从 `item` 转向了 `work-context`。

也就是说，系统不只是推荐“看什么”，而是在推荐：

- 围绕什么继续做
- 当前应该聚焦哪些对象
- 当前应该采用什么玩法模式
- 当前要继承什么 tension / goal / constraints

因此，推荐系统实际上是在给 agent 推荐：

> 当前 state 下最值得进入的 work-context

用户前台看到的是 card / offer / suggestion，而 agent 后台消费的是 working context bundle。

## 五、系统的两层结构

从全局上看，最合理的推荐结构不是单层，而是两层：

### 1. 世界内生层

回答：

- 这个世界自己，按当前已有角色、地点、作品、关系和 tension，下一步最自然该做什么

这一层负责：

- 自洽
- 连续性
- 世界内部的“好玩基因”
- 从已有内容自然长出的 continuation

### 2. 外部玩法注入层

回答：

- 有没有来自其他世界的玩法模式，可以增强当前世界的玩法表现

这一层不是把用户带去别的世界，而是从别的世界抽取可迁移的：

- play pattern
- narrative move
- pacing structure
- interaction template

再把它们适配并注入当前世界。

这两层共同构成一个更完整的生成式推荐系统：

- 第一层保证真实与自洽
- 第二层提供结构、新鲜感和玩法增强

## 六、为什么不能走纯规则，也不能走 LLM 端到端

纯规则的问题在于：

- 很难从 `works.content`、复杂对话和多轮会话里抽出真正的语义张力
- 很难识别什么是值得继续的 latent hook
- 很难做出有趣而不模板化的下一步

LLM 端到端的问题在于：

- 不可控
- 不可解释
- 成本高
- 难以稳定写回状态
- 很容易退化成“再生成 3 条文本建议”

因此，最合理的路线是：

> 规则搭骨架，LLM 插在少数高价值、难规则化的节点上

也就是一个：

> stateful, policy-controlled, LLM-augmented generative recommendation runtime

## 七、LLM 最适合插入的位置

LLM 在下一代推荐系统里，不应该主要负责最终排序，而更适合负责三类工作：

### 1. 语义钩子提取

从：

- works.content
- recent history
- tool results
- atom descriptions

中抽出：

- tension
- relationship
- lore gap
- visual opportunity
- goal shift

这类中间语义对象。

### 2. 外部玩法模式抽象

把别的世界里的玩法内容，抽象成可迁移的 play pattern，而不是直接搬运内容本身。

### 3. 最终 offer 文案重写

在候选已经被选定后，用 LLM 将内部 candidate 重写成更有画面感、更可点击、更像产品 surface 的文案。

不适合交给 LLM 的部分包括：

- 全量 policy 排序
- state writeback
- durable memory promotion
- 端到端 suggestions generation

## 八、State 的重新定义

下一代推荐系统中的 `state` 不再只是 profile，而是：

> 当前时间点下，支持下一步检索、决策、执行与写回的可操作现实

它至少包含几层：

- durable state
- session state
- working state
- outcome state

而工程上需要同时解决：

- context write protocol
- session compression
- memory promotion

因此，真正困难的不是“拿到更多上下文”，而是：

> 如何让不断增长的上下文在多轮协作中保持可决策、可压缩、可写回，而不被噪声污染

## 九、推荐系统与 agent 的关系

下一代推荐系统不应被理解为“给用户展示内容”的模块，而更像是：

> 给 agent 推荐当前 state 下最值得进入的 working context 和 next move 的引擎

因此，更合理的结构是：

```text
current context
-> recommendation / transition engine
-> choose next move
-> build working context
-> inject into agent
-> agent executes
-> world/session update
-> new context
```

这里的重点是：

- 不把全量 context 一股脑塞给 agent
- 而是先由推荐引擎决定下一步
- 再把裁剪过的 working context 注入给 agent 执行

## 十、Surface 的统一视角

不同 UI surface 不应被看作不同系统，而应被理解为同一个 recommendation runtime 的不同出口。

典型 surface 包括：

### 1. First-step / empty-state cards

例如：

- Adventure
- Lore
- Manga

它们是：

- first-step recommendation

### 2. Chat suggestions / continuation offers

它们是：

- in-flow next-step recommendation

### 3. Cross-world pattern injection

它们是：

- secondary inspiration / pattern augmentation layer

也就是说，统一的 runtime 可以输出：

- first-step recommendation
- next-step continuation
- play-pattern injection

只是投影到不同 surface。

## 十一、这一体系下的个性化应该怎么放

在传统推荐里，个性化是主干。

在这里，更合理的做法是：

- 先由 `world/task fit` 决定当前最合理的下一步
- 再由 `session fit` 决定强度、时机和形式
- 最后由 `user preference fit` 决定：
  - 哪种模式更优先
  - 哪种表达更适合
  - 外部玩法模式该偏向哪一类

也就是说，用户画像更适合作为：

- tiebreaker
- style bias
- pattern selector
- pacing modifier

而不是主决定项。

## 十二、系统演进路线

从当前实践出发，下一代推荐系统更现实的演进路线是：

### Phase 1

- 规则化 state / retrieval / policy 骨架
- 建立 recommendation runtime
- 验证 world + session 是否真的比轻上下文 suggestions 更强

### Phase 2

- 引入 LLM semantic hook extraction
- 用 hook 增强 recall 与 ranking
- 保持最终 policy 可控

### Phase 3

- 引入外部玩法模式注入层
- 抽象其他世界中的 play pattern
- 将其适配为当前世界的候选增强

### Phase 4

- 将个性化正式降为第三层调制项
- 优化 pattern selection、surface 表达和节奏控制

## 十三、最终结论

如果从全局定义下一代推荐系统，我会这样总结：

> 下一代推荐系统，是一个以 world/task 为核心、以 session 为驱动、以 user preference 为调制、由内生 continuation 与外部玩法注入共同构成的 context transition engine。

它不再只是为用户挑选内容，而是在：

- 理解当前 state
- 生成可能的下一步
- 选择最值得进入的下一个 context
- 将裁剪后的 working context 注入给 agent 或直接投影为用户可点的 offer
- 再通过执行和写回，使系统进入新的上下文

因此，它本质上不是：

- 搜广推的简单升级版
- 也不是“LLM 生成 3 条建议”的产品包装

而是：

> 一个由状态驱动、由 context 演化驱动、由乐趣与连续性共同优化的生成式推荐运行时。
